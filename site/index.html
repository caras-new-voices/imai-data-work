What IMAI is

An influencer-marketing SaaS: brands and agencies discover influencers (search across platforms), generate influencer reports (audience/performance analysis), run campaigns with automatic post tracking, build lists, do geo analysis, PR/journalist outreach, social listening, and brand-safety checks — plus a conversion pixel their e-commerce customers install to attribute sales to influencers. Sold two ways:

Self-serve engine

Stripe (+ Cardcom for Israel). 7-day free trial behind a card wall and an anti-abuse gate; day-7 autocharge converts. Observed price points: $99 / $175 / $499 / $599 / $959 / $1199–1200 + custom (plans are DB rows, not code). The growth funnel — but the minority of paying accounts.

Sales-led engine

Manual/invoiced enterprise deals managed in Close CRM — the majority of paying accounts and most of the dollars. Renewals are relationship-driven; ~280 of 561 manual payers have zero platform events ever. Largely invisible to product analytics.

The one-sentence story: the funnel is healing (June conversion doubled) but the self-serve revenue mix is shrinking — new cohorts buy small plans while high-value legacy payers roll off — and the biggest leak (signup→card) still emits no data at all. Details: Metrics & Money.

The system in one paragraph

The app is a monorepo (Discovery-imai) running entirely on Google Cloud — an Angular frontend, a NestJS main API, an Express proxy that meters every API call, plus social-listening, brand-safety and campaign-tracker services. Product analytics, however, exits the visible codebase: three fire-and-forget emitters POST events to an env-configured webhook whose receiver is unknown (Q1), which lands them in a separate "pixel" Postgres (~4.6M rows) and fans out to Mixpanel, Klaviyo and Close. A legacy AWS pixel collects page visits; a separate customer-facing pixel attributes e-commerce conversions. Full picture: Architecture.

Read this before trusting any number

The five rules (violating any of these has produced wrong numbers before):
  • Never compute dollars from webhook events — they captured ~36% of recurring dollars (June 2026). Dollars = prod user_payments + Close; Stripe-integration Mixpanel dollars are usable for the Stripe engine only (Q28).
  • Never mix Mixpanel namespaces in one KPI — "Login" vs user_logged_in, "Signup" vs signup, "Influencer Search" vs influencer_discovery_search (41% apart, Q25).
  • Exclude admin-created accounts from funnels; roll team members up via main_user_id.
  • Respect event birth dates: cancel_trial 2026-04-22, trial_* friction 2026-06-30 — trends crossing them are measurement changes. Same for the Jul-21 signup-flow change (onboarding events collapse) and trial search-window change.
  • payment_failed is dunning noise — count distinct users, never raw events.

Current health warnings

  • The audit's remediation patches (R1/R2/R8/R16/R21) were never merged — the proxy emitter is ungated, GA4/Slack/Bubble secrets are hardcoded in source, and there's no event CI guardrail. (Verified at HEAD 2026-07-22; register item Q29 asks whether prod ever ran them out-of-band.)
  • The single highest-leverage unknown is still Q1: one grep on the prod VM reveals the entire external analytics pipeline (and now also the pixel-DB host, Q3).
  • Two services run on the prod VM outside version control (Q8); event delivery is fire-and-forget with no retry anywhere — downstream gaps are by design.
