User journey map

One flowchart of the whole self-serve journey: every code touchpoint in sequence, the decision points, and the loops users circle back through. Solid arrows = forward path · dashed arrows = loops/returns · diamonds = decisions in code. File refs verified @ da98fcf2. Numbers = June/July 2026 measurements.

How to read it

  • Diamonds are real branches in code: the onboarding skip-list (since 2026-07-21 all IMAI signups bypass the wizard), the abuse gate (payments.service.ts:1545, blocking 31% of card-enterers with no recovery path), and quota enforcement (users.service.ts:1707/:1719).
  • The workspace hub is a loop, not a line — users bounce between the seven feature modules and return; each bounce is metered by the proxy and quota-checked server-side. The whole trial outcome is decided inside this loop's first ~4 hours (median cancel time).
  • Three circle-backs matter most: friction-modal dismiss → back to work (40% of trials see it); AI retention call → back from the cancel flow; and the paying-customer daily loop, which notably has no upgrade prompts — the expansion gap.
  • Two ends of the line: BLOCKED (gate) and CANCELED — after cancel, the only touchpoint left is Klaviyo lifecycle email.
  • The gray box at the bottom applies to every node: each step's event rides the fire-and-forget webhook pipeline to imai_events → Mixpanel/Klaviyo/Close.
